## 1. 概述

### 1.1 背景

本地主机 A 与远程主机 B 分处不同网络。A 侧产生的组播流量需要延伸到 B 侧网络，由 B 以组播形式重新发出，使 B 侧的组播接收者无需感知中间的转发链路。

### 1.2 目标

- 主机 A 在指定网卡上加入指定组播组，接收组播数据。
- 主机 A 通过 TCP 客户端将数据封装后发送给主机 B。
- 主机 B 通过 TCP 服务端接收数据，再从指定网卡以组播形式发往指定组播组和端口。
- 两端通过共享口令完成身份认证，防止未授权客户端接入。
- 保证载荷内容逐字节一致，报文边界不变。
- 提供图形界面，支持参数可视化配置、配置导入导出、启动自动加载与退出自动保存。

### 1.3 v1 范围

| 项目 | 范围 |
| --- | --- |
| 拓扑 | 1 个 A 到 1 个 B，单向 |
| 组播组 | 单组：A 接收 1 个组，B 发送 1 个组 |
| 传输层 | TCP |
| 网络协议 | IPv4（v1 不支持 IPv6） |
| 最大载荷 | 1024 字节/包 |
| 性能目标 | 1–100 包/秒 |
| 交付形态 | 单窗口图形界面程序，不做系统服务、不做安装包，拷贝目录即可运行 |
| 参数来源 | 组地址、端口、TTL、网卡等全部通过配置指定，不在协议中携带 |
| 认证方式 | 两端共享口令，HMAC-SHA256 挑战应答 |
| 部署环境 | 仅内网使用，不跨公网，不提供 TLS 加密 |
| 配置方式 | 界面内可视化编辑，支持导入/导出 INI，启动自动加载、退出自动保存 |

以下内容不在 v1 范围：双向隧道、多客户端接入、单连接多组复用、Web 管理界面、TLS 加密。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 组播组 | 一组接收者共同加入的 IP 组播地址，如 `239.x.x.x` |
| 入组 | 主机通过 IGMP 加入组播组，开始接收该组流量 |
| 网卡/接口 | 主机上的物理或虚拟网络接口 |
| 主机 A | 本地主机，组播接收方，同时是 TCP 客户端 |
| 主机 B | 远程主机，TCP 服务端，同时是组播发送方 |
| 载荷 | 单个 UDP 组播报文的数据部分，不含 IP/UDP 头 |
| 帧 | 隧道协议在 TCP 连接上传输的基本单位 |
| 认证口令 | 两端预先配置的共享密钥，用于客户端身份认证 |
| 挑战应答 | B 发送随机数，A 用口令计算 HMAC 后返回，避免口令明文传输 |

## 3. 系统架构

```text
[组播源] --UDP组播--> (网卡 A1) 主机A --TCP隧道--> 主机B (网卡 B1) --UDP组播--> [组播接收者]
```

数据流向：

1. 组播源向指定组播组和端口发送 UDP 数据。
2. 主机 A 在配置的网卡上入组，收到载荷后按协议分帧。
3. 主机 A 作为 TCP 客户端连接主机 B，完成口令认证后将帧发送给主机 B。
4. 主机 B 认证通过后从 TCP 连接解帧，将载荷原样发往配置的组播组、端口和出口网卡。

## 4. 功能需求

### 4.1 主机 A（客户端）

#### FR-A1 组播接收

- 加入配置指定的组播组和端口。
- 必须在配置指定的网卡/接口上入组，不得依赖系统默认路由。
- 实现说明：组播接收通过 `IP_ADD_MEMBERSHIP` 在指定网卡上入组，而不是把 socket 绑定到该网卡的 IP；接收 socket 默认绑定 `0.0.0.0`。
- 按最大 1024 字节载荷设计接收缓冲区。
- 载荷超过 1024 字节的包直接丢弃并计数，不做截断。
- v1 不转发长度为 0 的 UDP 载荷，收到后丢弃并计数（数据帧长度范围为 1 到 1024）。
- 仅转发目的组播地址与配置组播组一致的报文；如同一 UDP 端口存在其他组播组，应通过 `IP_PKTINFO` 获取目的地址并过滤，或在部署上避免端口冲突。
- 不修改载荷内容，不做去重、排序或重组。

#### FR-A2 TCP 发送

- 作为 TCP 客户端连接主机 B 的配置地址和端口。
- 按第 5 章协议完成认证并封装数据帧，保持原始 UDP 报文边界。
- 启用 `TCP_NODELAY`，避免 Nagle 算法引入额外延迟。
- 发送失败不重试单个数据包。

#### FR-A3 连接管理

- 启动后立即连接主机 B；连接失败或断开后自动重连。
- 连接失败或断开后固定每 3 秒重试一次，不再做指数退避：既缩短恢复时间，也避免重试日志刷屏（仅首次失败记一条警告）。
- 断线期间收到的组播包直接丢弃，不缓存、不补发；恢复后从当前包继续转发。
- 通过 TCP Keepalive 或应用层心跳检测半开连接。

#### FR-A4 队列与背压

- 组播接收与 TCP 发送之间使用有界队列，默认容量 1024 包。
- 队列满时默认丢弃最旧的数据包（实时性优先），并累加丢弃计数。
- 队列写入不得阻塞组播接收循环。

### 4.2 主机 B（服务端）

#### FR-B1 TCP 监听

- 在配置的监听地址/网卡和端口上监听。
- v1 同一时刻仅维护 1 个活动会话；新连接完成认证后替换旧连接，关闭旧会话并接管转发，避免半开连接导致重连被拒。
- 按第 5 章协议完成认证和解帧；未知类型、数据帧长度为 0 或超过 1024 字节、控制帧长度不为 0 的帧视为非法帧，立即断开连接并记录日志。
- 连接断开后清理会话状态，继续监听，等待 A 重连。

#### FR-B2 组播发送

- 将收到的载荷原样发往配置的组播组和端口。
- 不保留原始组播报文的源 IP 和源端口；源 IP 为出口网卡地址，源端口由系统分配。使用 SSM 或按源地址过滤的接收端需评估兼容性。
- 出口网卡由配置指定，通过 `IP_MULTICAST_IF` 绑定。
- 组播 TTL 可配置，默认 1。
- 组播回环 `IP_MULTICAST_LOOP` 可配置，默认开启，便于同机调试。
- 同机部署时，发送组播组/端口必须与主机 A 的接收组播组/端口不同，或关闭回环，避免形成转发环路。
- 单包发送失败时记录日志并计数，不中断 TCP 连接。

#### FR-B3 会话管理

- 同一时刻仅维护一个活动会话。
- 记录最后一次收到主机 A 数据帧或控制帧的时间，超过心跳超时时间（默认 30 秒）未收到任何帧时，判定对端失联并主动关闭连接。

### 4.3 认证与安全

#### FR-A5 客户端认证

- 必须在配置的 `[auth] password` 中设置认证口令，口令按 UTF-8 编码参与计算；建议长度不少于 8 个字符。
- 收到主机 B 的 16 字节挑战码后，计算 `HMAC-SHA256(password, "MCFW" || version || nonce)` 并返回 32 字节结果。
- 认证失败时输出 error 日志，并按最大退避间隔（默认 30 秒）重连。
- 日志与统计中不得出现口令明文或完整 HMAC 值。
- 认证口令建议仅通过配置文件提供，避免通过命令行参数传递而暴露在进程列表中。

#### FR-B4 服务端认证

- 每次连接使用系统密码学安全随机数生成器生成 16 字节挑战码，禁止复用。
- 使用常量时间比较校验主机 A 返回的 HMAC。
- 认证失败时返回失败标志并关闭连接；对外日志不区分具体失败原因。
- 同一来源连续认证失败时，可增加 1 秒延迟，降低暴力破解速率。
- v1 为单向认证：主机 B 验证主机 A，主机 A 不验证主机 B。

### 4.4 配置管理

- 配置文件采用 INI 格式，配置示例见 6.3。
- 程序启动时自动加载可执行文件同目录下的 `config.ini`；文件不存在则载入内置默认值并在界面提示。
- 启动转发时、以及关闭窗口时，自动把当前界面参数保存回 `config.ini`。
- 支持**导出配置**：把当前界面参数另存为指定 INI 文件，便于批量下发。
- 支持**导入配置**：从任意 INI 文件载入参数到界面，导入后立即生效于界面并写回 `config.ini`。
- 在界面上直接修改参数即可，无需手工编辑文件；网卡以下拉列表形式给出本机可选地址，并提供"刷新"按钮。
- 启动转发前校验必填项、组播地址合法性、端口范围、网卡是否存在、认证口令是否为空；校验失败在界面弹出明确原因，不进入运行态。
- 配置文件加载时**先解析、后校验**：即使某项不合法（如配置的网卡在本机不存在），也照常载入其余参数供用户修正，不整体丢弃。
- 配置项清单见第 6 章。

> 说明：控制台版本（`mc_forward_a` / `mc_forward_b`）仍保留配置文件与命令行参数两种方式，命令行优先级高于配置文件；认证口令不允许通过命令行传入。

### 4.5 日志与统计

- 日志级别：error、warn、info、debug。
- 统计项：接收包数、发送包数、字节数、丢弃包数、队列深度、重连次数、认证失败次数、当前连接状态。
- v1 通过日志周期性输出统计；HTTP `/stats` 或 Prometheus 指标为可选项。

### 4.6 图形界面

#### FR-G1 角色与参数

- 单一窗口内通过单选按钮选择**客户端**或**服务端**角色，同一份程序兼顾两端，无需两套部署包。
- 选择角色后，只显示该角色相关的配置分组（客户端的"服务端连接"或服务端的"监听"），避免误填无关项。
- 界面分为：顶部菜单栏（文件：导入/导出/退出；帮助）、左侧参数区、左下操作按钮（启动/停止、导入配置、导出配置）、右上状态区、右下运行日志区、底部状态栏（常驻显示当前配置文件路径，可选中复制）。

#### FR-G2 运行控制

- 【启动】按钮执行校验并进入运行态；运行期间参数区整体禁用，按钮变为【停止】。
- 状态区实时显示连接状态（未运行 / 运行中·已连接 / 运行中·重连中 / 运行中·等待客户端）。
- 状态区以**两行表格**显示进口与出口流量，列为：方向、包数、字节数、包/秒、字节/秒；数值单元格只显示数字，单位体现在表头：
  - 客户端：进口 = 组播收包，出口 = 隧道转发；
  - 服务端：进口 = 隧道收到，出口 = 组播发出。
- 丢弃分类计数、队列深度、重连次数、认证失败次数**不在界面显示**，只写入运行日志，保持状态区简洁。
- 运行日志区实时滚动显示与文件日志一致的内容，错误、警告用不同颜色区分。

#### FR-G3 配置导入导出

- 【导出配置】把当前界面参数写成 INI 文件，供其他机器复用；默认文件名按角色区分（`config-client.ini` / `config-server.ini`）。
- 【导入配置】读取 INI 并回填界面，包括运行角色；导入后自动保存为本地 `config.ini`。
- 导入/导出同时提供菜单【文件】入口与快捷键（Ctrl+O 导入、Ctrl+S 导出）；运行中禁用，避免中途改参数导致界面与实际运行不一致。

#### FR-G4 自动加载与保存

- 启动时自动加载同目录 `config.ini`；不存在则使用内置默认值。
- 启动转发与关闭窗口时自动保存 `config.ini`，用户无需手动保存。
- 状态栏始终显示当前 `config.ini` 的完整路径。
- 参数异常时在日志区给出提示，不阻止程序启动，便于现场边改边试。

- **FR-G5 高 DPI**：界面必须在 125% / 150% / 200% 缩放下正常显示；字号跟随系统默认字体，不使用固定 px 值，避免高分辨率屏幕上文字过小。

### 4.7 远程更新（可选）

服务端部署在远端、不方便现场操作时，客户端可把本地 `multicastForward.exe` 推送到服务端，由服务端自行替换并重启。

- **FR-U1 触发方式**：仅由客户端手动发起（菜单「工具 → 远程更新服务端…」），不自动比对版本、不静默升级；运行中不可用，需先停止转发。
- **FR-U2 传输**：复用现有 TCP 隧道，认证通过后发送专用帧；**固定 1 KB 一块**，不涉及 UDP，也不会放大接收缓冲。
- **FR-U3 完整性**：客户端先计算整包 SHA-256 并在 `UPDATE_BEGIN` 中声明；服务端逐块写入 `multicastForward.exe.new`，收齐后重新计算比对，**不一致则丢弃且不改动现有程序**。
- **FR-U4 替换与重启**：校验通过后交给同目录的「启动器」`multicastForwardLauncher.exe`：等待主程序退出 → 备份为 `.old` → 替换 → 启动 → 4 秒存活检测；新版本立即退出则自动回滚并重启旧版本。
- **FR-U5 启动器**：独立可执行程序，**不依赖 Qt / MFC**，主程序因缺少运行库起不来时仍能回滚；支持 `--apply` 一次性替换，以及不带参数的守护模式（见 4.8）。
- **FR-U6 审计**：启动器把每次替换、回滚写入同目录 `launcher.log`；服务端日志记录接收大小与 SHA-256 前缀。
- **FR-U7 约束**：v1 只更新 exe 本体，不更新 Qt / VC 运行库；若新版本引入新依赖，需现场或远程桌面整包替换。

> 安全提示：按当前需求，服务端**始终允许**持有正确口令的客户端更新程序，等同于授予该主机的程序执行权。现场必须使用强口令，并把 TCP 端口限制在可信网段可达范围。

### 4.8 启动器守护

服务端位于远端、无人值守，主程序被关闭后必须能自行恢复，且守护进程本身不能被随手关掉。

- **FR-L1 通知区域驻留**：启动器无参数启动后**不显示任何窗口**，只在 Windows 通知区域放一个图标（双击图标等同「显示主程序窗口」）；任务栏与 Alt+Tab 中不可见，避免误关。
- **FR-L2 自动拉起**：主程序退出后 **3 秒**自动重新拉起，不区分退出码（正常关闭与崩溃一视同仁）。连续快速失败（启动后 5 秒内即退出）时按 6 / 12 / 24 / 30 秒递减频率重试，避免崩溃风暴占满日志。
- **FR-L3 退出方式**：**只有**通知区域右键菜单【退出守护】才能结束启动器（需二次确认）；退出不关闭正在运行的主程序，只是不再自动拉起。系统关机 / 注销时不再拉起。
- **FR-L4 不重复启动**：同一目录只允许一个守护实例；重复启动只提示「已在运行」并退出。每轮拉起前先按进程名探测，若主程序已在运行（人工启动或更新后由启动器拉起）则接管监控，不再启动第二个实例。
- **FR-L5 托盘菜单**：显示主程序窗口 / 打开运行日志 / 退出守护；主程序窗口最小化时还原并置前。
- **FR-L6 审计**：启动、拉起、退出（含退出码）、替换、回滚、重试间隔全部写入同目录 `launcher.log`。
- **FR-L7 缺失配置提示**：同目录没有 `config.ini` 时在日志中明确告警，避免「模板没复制成 config.ini」导致反复重启难以排查。

## 5. 协议设计（v1）

### 5.1 总体约定

- 承载协议：TCP；主机 A 为客户端，主机 B 为服务端。
- 字节序：大端（网络字节序）。
- 最大帧长：1 + 2 + 1024 = 1027 字节。
- 组播参数由两端配置决定，不在报文中传输。
- 认证在握手阶段完成，采用单向认证：主机 B 验证主机 A。

### 5.2 握手与认证

握手阶段使用固定长度字段，不套用后续的 `type + length + payload` 帧格式。

```text
主机A                                主机B
  | ---- HELLO (8B) ----------------> |
  | <--- CHALLENGE (16B) ------------ |
  | ---- AUTH (32B) ----------------> |
  | <--- AUTH_RESULT (1B) ----------- |
  | ======== 数据/控制帧 ============ |
```

#### 1. HELLO（A 到 B，8 字节）

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| magic | 4 字节 | 固定字符串 `MCFW` |
| version | 1 字节 | 当前为 `0x01` |
| flags | 1 字节 | 保留，置 0 |
| reserved | 2 字节 | 保留，置 0 |

主机 B 校验 magic 与 version；不匹配，或 `flags`、`reserved` 不为 0 时，关闭连接。

#### 2. CHALLENGE（B 到 A，16 字节）

- 每次连接使用系统密码学安全随机数生成器生成，禁止复用。

#### 3. AUTH（A 到 B，32 字节）

- 计算方式：`HMAC-SHA256(key = password, data = "MCFW" || version || nonce)`，其中 `password` 为 `[auth] password` 配置值。
- 其中 `||` 表示字节拼接，`version` 为 1 字节，`nonce` 为 16 字节挑战码。

#### 4. AUTH_RESULT（B 到 A，1 字节）

- `0x00` 表示认证成功，`0x01` 表示认证失败。
- 认证失败后主机 B 立即关闭连接。

#### 5. 握手约束

- 整个握手应在 5 秒内完成，超时则关闭连接。
- 认证完成前，双方不得发送数据帧或控制帧。
- 认证成功后才能进入正常的数据转发阶段。

### 5.3 数据帧

```text
+--------+----------------+------------------------+
| type   | length         | payload                |
| 1 字节 | 2 字节（大端） | 1 ~ 1024 字节          |
+--------+----------------+------------------------+
```

- `type`：`0x01` 表示数据帧。
- `length`：载荷字节数，合法范围 1 到 1024。
- `payload`：原始 UDP 载荷，逐字节透传。

### 5.4 控制帧

| type | 名称 | length | 说明 |
| --- | --- | --- | --- |
| `0x02` | PING | 0 | 心跳请求 |
| `0x03` | PONG | 0 | 心跳响应 |

- 主机 A 每 10 秒发送一次 PING，主机 B 收到后回复 PONG。
- 主机 A 连续 3 次未收到 PONG 判定连接失效，主动重连。
- 主机 B 超过心跳超时时间（默认 30 秒）未收到主机 A 的任何帧，判定对端失联并关闭连接。
- 收到未知 type 时视为非法帧，按 FR-B1 处理：断开连接并记录日志。

### 5.5 传输规则

- 接收端严格按 `length` 读取 payload，不足则继续等待。
- 长度非法时立即断开连接，防止内存被异常帧撑大。
- 不做应用层重传，可靠性由 TCP 保证。
- 接受 TCP 可靠有序特性带来的队头阻塞和延迟抖动，v1 不提供 UDP 承载模式。

## 6. 配置项

### 6.0 公共项

| `server.host` | 主机 B 地址 | 无 | 是 |
| `server.port` | 主机 B 的 TCP 端口 | 无 | 是 |
| `auth.password` | 与主机 B 一致的认证口令 | 无 | 是 |

| 配置项 | 含义 | 默认值 | 必填 |
| --- | --- | --- | --- |
| `listen.host` | TCP 监听地址/网卡 | `0.0.0.0` | 是 |
| `listen.port` | TCP 监听端口 | 无 | 是 |
| `auth.password` | 与主机 A 一致的认证口令 | 无 | 是 |
| `multicast.group` | 发送目标组播组地址 | 无 | 是 |
| `multicast.port` | 发送目标端口 | 无 | 是 |

| `runtime.log_level` | 日志级别 | info | 否 |

### 6.3 配置示例

主机 A（客户端，`config.ini`）：

```ini
[app]
role = client

[multicast]
group = 239.255.10.128
port = 9302
interface = 192.168.1.66

[server]
host = 172.16.5.213
port = 25000

[auth]
password = change-me

[runtime]
queue_size = 1024
reconnect_min = 1
reconnect_max = 30
heartbeat_interval = 10
heartbeat_timeout = 30
log_level = info
```

主机 B（服务端，`config.ini`）：

```ini
[app]
role = server

[listen]
host = 0.0.0.0
port = 25000

[multicast]
group = 239.255.10.229
port = 9302
interface = 172.16.5.213
ttl = 1
loop = true

[auth]
password = change-me

[runtime]
heartbeat_timeout = 30
reconnect_min = 1
reconnect_max = 30
heartbeat_interval = 10
log_level = info
```

两端组地址不同（`.129` 收 / `.229` 发）但端口相同，客户端的目的地址过滤会把 B 发出的流量丢弃，不会形成环路。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 载荷上限 | 单个组播包载荷最大 1024 字节（不含 IP/UDP 头） |
| 吞吐 | 1–100 包/秒；按 1024 字节包计算峰值约 0.8 Mbps |
| 延迟 | 单跳额外延迟目标不超过 10ms（内网直连，非硬性验收项） |
| 稳定性 | 支持 7×24 小时运行，异常断开后自动恢复 |
| 资源占用 | 常驻内存目标不超过 50MB |
| 平台 | Windows / Linux，使用同一套代码跨平台构建 |
| 认证 | 两端共享口令，HMAC-SHA256 挑战应答 |
| 传输安全 | 仅内网使用，不跨公网，不加密 |

安全说明：认证口令以明文保存在配置文件中，应通过文件系统权限限制读取；日志和统计中不得输出口令或完整 HMAC 值。v1 为单向认证，不提供传输加密，不建议直接在公网部署。

## 8. 异常与边界

| 场景 | 预期行为 |
| --- | --- |
| A 启动时 B 未启动 | A 持续重连，日志限频输出 |
| TCP 连接闪断 | A 自动重连，断线期间的组播包丢弃 |
| B 重启 | A 自动恢复连接，无需人工干预 |
| 组播源停止发送 | 保持 TCP 连接，无数据转发 |
| 单个组播包超过 1024 字节 | A 丢弃并累加计数 |
| B 收到非法帧 | 断开连接并记录日志，继续监听 |
| TCP 半开连接 | 心跳超时后主动断开 |
| 认证口令不一致 | B 返回认证失败并断开；A 记录 error 日志，按最大退避重连 |
| 握手超时 | 主动断开连接，A 按退避策略重连 |
| 认证口令为空 | 启动校验失败，进程退出并提示配置错误 |
| 配置错误 | 启动失败并输出明确错误信息 |
| 同机自测 | 发送组/端口应与 A 的接收组/端口不同，或关闭 B 的回环；否则可能形成转发环路 |

## 9. 验收标准

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| AC-01 | 指定网卡入组 | 仅在配置网卡上接收组播数据 |
| AC-02 | 透传一致性 | 1 到 1024 字节的包，B 侧发出的载荷与 A 侧接收的载荷逐字节一致，包边界一致 |
| AC-03 | 网卡隔离 | 从非指定网卡发送同组数据，A 不转发 |
| AC-04 | 断线重连 | 断开网络 30 秒后恢复，A 在最大退避时间内自动重连 |
| AC-05 | B 重启恢复 | B 重启后 A 自动重连成功 |
| AC-06 | 背压保护 | 以超过链路能力的速率发送时，进程内存保持稳定，丢弃计数持续增长 |
| AC-07 | 超长包处理 | 1025 字节的包被 A 丢弃并计数 |
| AC-08 | 非法帧处理 | B 断开非法连接且不影响后续正常重连 |
| AC-09 | 长稳运行 | 连续运行 24 小时无崩溃、无内存泄漏 |
| AC-10 | 认证成功 | 两端配置相同口令时可正常建立会话并转发数据 |
| AC-11 | 认证失败 | 两端口令不一致时 B 拒绝连接，A 无法转发，日志中不出现口令明文 |
| AC-12 | 组地址过滤 | 同一 UDP 端口上其他组播组的数据不被转发 |
| AC-13 | 吞吐能力 | 以 100 包/秒、1024 字节/包持续发送 10 分钟，转发正常且内存无明显增长 |
| AC-14 | 界面启动 | 双击程序即可打开主窗口，参数区完整、无乱码；切换角色后仅显示该角色相关分组 |
| AC-15 | 自动加载与保存 | 修改参数并启动后关闭程序，再次启动时界面恢复上次参数；删除 `config.ini` 后启动使用默认值并给出提示 |
| AC-16 | 导入导出 | 导出到新文件后，在另一台机器导入，界面参数与角色完全一致，可直接启动 |
| AC-17 | 同端口共存 | 本机已有其他程序监听同一组播端口时，客户端仍能正常入组收包（共享绑定） |
| AC-18 | 远程更新成功 | 推送与当前一致的 exe，服务端校验通过后自动重启，转发在数秒内恢复，日志可见「已替换 / 运行正常」 |
| AC-19 | 远程更新回滚 | 推送一个启动即退出的程序，启动器在 4 秒存活检测后回滚到旧版本并恢复服务 |
| AC-20 | 更新完整性 | 传输内容任意字节被篡改时，服务端 SHA-256 不匹配，拒绝替换并保留原程序 |
| AC-21 | 启动器自动拉起 | 关闭（或强杀）主程序后 3 秒内自动出现新进程，转发恢复；守护期间通知区域有图标、无可见窗口 |
| AC-22 | 启动器退出控制 | 除通知区域右键【退出守护】外无法结束启动器；退出后主程序继续运行且不再自动拉起；重复启动不产生第二个实例 |

## 附录 A 技术选型建议（非强制）

结合现有开发环境（MSVC `cl` + Qt），建议使用 **Qt 6 或 Qt 5.15 的 C++ 控制台程序**，只依赖 Qt Core 和 Qt Network：

- 入口使用 `QCoreApplication`，不创建 GUI，构建时关闭 Qt GUI 模块。
- 建议同一个可执行文件通过 `--role client|server` 选择角色，A/B 共用协议、认证和配置代码，分别加载各自的 INI 文件。
- 组播收发使用 `QUdpSocket`：A 通过 `joinMulticastGroup(group, iface)` 在指定网卡入组；B 通过 `setMulticastInterface(iface)` 指定出口网卡，用 `MulticastTtlOption` 和 `MulticastLoopbackOption` 设置 TTL 与回环。
- 收包时优先用 `QNetworkDatagram::destinationAddress()` 过滤目的组地址；若平台不提供该信息，则通过部署上避免同端口多组来规避。
- TCP 使用 `QTcpServer` / `QTcpSocket`，用 `LowDelayOption` 对应 `TCP_NODELAY`。
- 认证使用 `QMessageAuthenticationCode` 计算 HMAC-SHA256，`QRandomGenerator::system()` 生成 16 字节挑战码。
- 认证比较需自行实现常量时间比较；发送侧使用有界队列，并仅在 `QTcpSocket::bytesToWrite()` 低于阈值时写入，避免 Qt 内部发送缓冲无限增长。
- 配置使用 `QSettings` 读写 INI，直接对应 6.3 的配置示例；使用 Qt 5 读取含非 ASCII 口令的 INI 时需设置 `QSettings::setIniCodec("UTF-8")`，建议口令使用 ASCII 字符。
- 1–100 包/秒的负载下，单线程事件驱动模型足够，不需要额外工作线程。
- 构建建议使用 CMake，链接 `Qt6::Core`、`Qt6::Network`（Qt 5 对应 `Qt5::Core`、`Qt5::Network`）。
- 部署时用 `windeployqt --console` 收集 Qt 运行库；如需单文件发布，可使用静态 Qt 构建。
- Windows 首次运行需放行 TCP 监听端口和组播 UDP 端口的入站防火墙规则。

备选方案：**Go**。单文件可执行、部署简单，`x/net/ipv4` 对组播网卡控制成熟，适合不想携带 Qt 运行库的场景；缺点是需要在现有 `cl` + Qt 环境之外额外安装 Go 工具链。

不建议从零使用裸 Winsock 实现：Qt 已覆盖组播网卡绑定、TCP、HMAC 和 INI 读写，可以显著减少 Windows/Linux 平台差异和开发量。
